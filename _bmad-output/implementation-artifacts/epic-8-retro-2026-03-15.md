## 🚨 Significant Discovery

**Epic 8 revealed that the majority of implemented commands do not justify their complexity.**

The analysis:

| Command | Verdict | Reason |
|---|---|---|
| `build` | ✅ Keep | MSBuild noise is massive, consistent, and always present |
| `restore` | ✅ Keep | Package download progress is enormous noise |
| `clean` | ✅ Keep | Deterministic, always safe to compress to `✓` |
| `test` | ✅ Keep | xUnit/MSTest output is verbose; failure structure adds real value |
| `publish` | ❌ Remove | Output already compact; savings required inflated baseline to demonstrate |
| `pack` | ❌ Remove | Same as publish — modest gains don't justify maintenance cost |
| `run` | ❌ Remove | Stripping 3 preamble lines isn't worth the complexity |
| `format` | ❌ Remove | Output already small; SDK-10 format changes made filter brittle |
| `nuget` | ❌ Remove | `locals` output is tiny; `push` is niche; not a real LLM workflow |
| `ef` | ❌ Remove | Delegates to a third-party tool with version-dependent output we don't control |
| passthrough | ❌ Remove | Only existed to handle the commands we're now deleting |

**Decision:** Delete all non-core commands and all related code. The tool's identity is now explicit: **dtk is a token reducer for the four high-noise MSBuild commands: build, restore, clean, test.**

**Timing is right:** The tool is pre-release (not yet published to NuGet.org). This is the correct moment for breaking changes.

---

## Key Insights

1. **Build end-to-end before declaring scope final** — integration testing surfaced that several filters added complexity without proportional value. The act of testing them against real SDK output was what revealed the problem.
2. **Spectre.Console silently drops unknown `--flags`** — any command arg forwarding requires the `--` separator to route options through `context.Remaining.Raw`. This is a cross-epic pattern that belongs in MEMORY.md.
3. **`--verbosity normal` is required to generate enough raw output for savings threshold tests** — pass it to `RunDotnetAsync` only; `RunDtkAsync` can receive it but Spectre drops it (no behavior change needed).
4. **Foundation stories pay the incident tax** — 8.2 had 6 debug incidents as the test infrastructure story. This is expected and not a team performance issue.
