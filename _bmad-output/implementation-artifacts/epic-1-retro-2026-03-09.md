- **Knowledge capture** — analyzer pitfalls and library API discoveries documented immediately in MEMORY.md and project-context.md; future stories won't repeat the same surprises
- **Deliberate suppressions** — all `.editorconfig` suppressions (CA1031, CA1303, CA1515, CA1819) were intentional and documented, not lazy workarounds

---

## Challenges

- **Library API surprises on uncommon versions** — Spectre.Console.Cli 0.53.x has undocumented behaviors (TypeRegistrar naming conflict, 3-param `ExecuteAsync`, positional args not in `Remaining.Raw`); Verify.Xunit v28 has breaking API changes (`[UsesVerify]` removed, `VerifyBase` breaks under xUnit reflection)
- **Story 1.3 complexity** — 6 debug incidents, the most of any story; inherent to the composition root / DI wiring / CLI framework integration role — structural complexity, not a process problem
- **Analyzer strictness as friction** — `TreatWarningsAsErrors=true` + `AnalysisLevel=latest-all` means every surprise is a build failure; this is correct in principle but amplified the cost of each discovery

---

## Key Insights

1. **Library API discovery is a one-time cost** — document immediately and move on; the mitigation is MEMORY.md, not relaxing the tooling constraints
2. **`TreatWarningsAsErrors` is an asset** — the `.editorconfig` escape valve provides the right safety mechanism without compromising the baseline quality gate
3. **Story 1.3 (composition root) is structurally the hardest story in any Clean Architecture epic** — budget accordingly in future projects
4. **The filter testing pattern is proven and reusable** — fixtures + snapshots + savings gate covers all the right verification angles
