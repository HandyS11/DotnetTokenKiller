## Challenges

- **Blueprint `files NOT to touch` invalidated by own ACs (7.1):** Story spec explicitly said "no .cs changes" but AC #3 (`dtk --version` → `0.1.0`) required touching `Program.cs`. The dev agent correctly prioritised the AC, but the blueprint created unnecessary cognitive friction. Blueprint scope constraints must be validated against all ACs before being written.
- **Config schema accuracy in blueprint examples:** The README example in Story 7.1 blueprint referenced a nonexistent `verbosity` field in `DtkConfig`. Small issue, but caught in review rather than authoring. Blueprints that include config/DTO examples should cross-check against the actual model types.

---

## Key Insights

1. **Zero-debt foundations make packaging epics fast** — when nothing is broken, packaging is just metadata. Epic 7 had nothing to work around.
2. **Blueprint `files NOT to touch` constraints must be validated against ACs** — if an AC explicitly requires a file change, the constraint is wrong, not the AC.
3. **The review gate is the last line before users see documentation errors** — config example issue in 7.1 README was caught there, but earlier detection (blueprint authoring) is preferable.
