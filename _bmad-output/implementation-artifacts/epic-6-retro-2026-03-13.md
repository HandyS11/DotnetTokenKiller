## Challenges

- **Blueprint `internal` constructor — recurring (3rd consecutive epic):** Story blueprints specified `internal` testability constructors for both `JsonConfigProvider` (6.1) and `FileTeeService` (6.2). Both had to be changed to `public` — the project has no `[InternalsVisibleTo]` attribute and the established convention (from `SqliteTracker` in Epic 5) uses `public` overloads. This is a blueprint authoring issue, not a developer error; it created unnecessary cognitive friction in both stories.
- **Story 6.2 code review catches:** DI registration still referenced `NullTeeService` instead of `FileTeeService` (functional correctness issue); AC #9 (slug sanitization) had no test coverage. Both caught in review before merge — the review gate worked as intended, but earlier detection would be preferable.

---

## Key Insights

1. **Blueprint `internal` constructors are wrong for this project** — always use `public` testability overloads; no `[InternalsVisibleTo]` exists and none is needed; fix the blueprint template for Infrastructure services
2. **Incident counts are trending down** — the Infrastructure layer is no longer new territory; established patterns are being applied correctly on first attempt
3. **The review gate catches what blueprints miss** — DI registration error and missing AC test in 6.2 were caught before merge; the process works; higher-confidence blueprints will further reduce review churn
